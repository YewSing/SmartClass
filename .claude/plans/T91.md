# T91 — Lecturer app: materials status + sync button + question trends

## Files to change
- `mobile/lecturer/src/screens/LecturerAssistant.jsx` — new screen.
- `mobile/lecturer/src/navigation/AppNavigator.jsx` — a new "AI Assistant" tab + stack.
- `mobile/lecturer/src/services/api.js` — `getAssistantCourses`, `getMaterials`, `syncMaterials`,
  `getQuestionTrends`.
- `backend/scripts/e2e_assistant.py` — seed/teardown for the Maestro flow.
- `mobile/lecturer/e2e/assistant.yaml` + `assistant.setup.sh` — the Maestro flow.
- `backend/tests/test_e2e_assistant_seed.py` — tests for the seed script.

## Approach
The endpoints already exist (T80 `GET /kb/courses/{id}/materials`, T81 `POST /kb/courses/{id}/sync`,
T87 `GET /lecturer/assistant/trends/{course_id}`); this task is the lecturer UI over them.
- A new "AI Assistant" tab (sparkles icon) hosting a `LecturerAssistant` screen: a course picker
  (the lecturer's courses from `GET /lecturer/assistant/courses`), a "Sync materials" button, the
  materials list with status badges (indexed/no_text/unsupported/error/pending), and the three
  trend lists.
- The Maestro flow logs in as `lecturer1`, opens the tab, taps Sync, then asserts the seeded
  material shows "Indexed" and all three trend lists appear.

## Edge cases
- Course with no materials yet → "No materials in this course."; a status outside the known set
  still renders its raw string.
- The sync toast is "Materials synced (N new, M updated)"; on a Moodle error the screen shows the
  error toast and the (locally seeded) materials list still renders.
- The seed script's material is `source="local"`, so a Moodle sync never deletes it.

## Tests
- `test_e2e_assistant_seed.py` (2 db): seeded material is indexed and all three trend lists have
  their topics; re-seeding is idempotent and teardown removes the material + chats.
- Maestro `lecturer assistant` PASS; lecturer `npm test`; check.sh.
