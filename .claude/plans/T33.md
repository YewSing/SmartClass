# T33 — Reports + CSV export for course/date range (FR-310)

## Goal
A lecturer can get an attendance report for **one session** and for **one class over a date range** (`from`/`to`, inclusive, by the class's MYT date), as CSV. The class report is students × closed sessions, every cell one of the four statuses (P/L/E/A), followed by each student's four status counts, attended/counted and the rate, computed with T32's `StatusCounts` (one formula everywhere). A JSON version of the same class report backs a future Reports screen (UC "System shows the table of students × sessions with rates").

Done when: CSV for a session and for a class over `from`/`to` (students × sessions showing all four statuses + rate); tests check headers and rows; `bash scripts/check.sh` passes; reviewer finds no real problems.

**Decision: "course" = class (`class_occurrences` row).** Lecture and tutorial of one course are separate classes with separate rosters and lecturers, and T32's lecturer view (`/lecturer/classes/{id}/attendance/rates`) is per class for NFR-04. The report is per class too. Do not build a cross-occurrence course report.

### 1. `backend/app/services/attendance_stats.py` — add `class_report`
```python
REPORT_SESSION_STATUSES = ("closed",)  # only finalised sessions go into a report (same rule as the rate)

async def class_report(
    db: AsyncSession, occurrence_id: int, from_date: date | None = None, to_date: date | None = None,
) -> tuple[list[AttendanceSession], list[dict]]:
    """Closed sessions of one class between from_date and to_date (inclusive, by session_date),
    oldest first, and one row per enrolled student (ordered by matric no):
    {"student_id", "matric_no", "name", "statuses": [status per session, same order], "counts": StatusCounts}.
    A missing record in a closed session is absent."""
```
Implementation:
- Students: same query as `class_student_rates` (Student + user, join Enrollment on occurrence, order by `Student.matric_no`). Factor the query into a private `async def _class_students(db, occurrence_id) -> list[Student]` and use it from both `class_student_rates` and `class_report` (no behaviour change for T32).
- Sessions: `select(AttendanceSession).where(occurrence_id == ..., status == "closed")`, then filter **in Python** with `d = session_date(sess)`: drop when `from_date and (d is None or d < from_date)` or `to_date and (d is None or d > to_date)`. Sort by `(session_date(s) or date.min, s.starts_at or s.opened_at or datetime.min, s.id)`.
- Records: ONE query for all kept session ids: `select(AttendanceRecord.session_id, AttendanceRecord.student_id, AttendanceRecord.status).where(AttendanceRecord.session_id.in_(ids))` (skip when no sessions) → dict `(session_id, student_id) -> status`.
- Per student: `statuses = [lookup.get((s.id, stu.id), "absent") for s in sessions]`; `counts = StatusCounts()`; `counts.add(x)` for each.
- Return `(sessions, rows)`.

Add a helper in the same file:
```python
def session_label(sess: AttendanceSession) -> str:
    """'YYYY-MM-DD HH:MM' (MYT) of the class; date only when no start time is stored."""
    d = session_date(sess)
    start = sess.starts_at or sess.opened_at
    day = d.isoformat() if d else ""
    return f"{day} {start.strftime('%H:%M')}".strip() if start else day
```

### 1b. `backend/app/services/attendance_stats.py` — add `resolve_date_range`
```python
def resolve_date_range(
    from_: date | None, to: date | None, from_date: date | None = None, to_date: date | None = None,
) -> tuple[date | None, date | None]:
    """`from`/`to` (FR-310), with the older `from_date`/`to_date` names still accepted.
    Raises ValueError when from is after to."""
    start = from_ or from_date
    end = to or to_date
    if start and end and start > end:
        raise ValueError("'from' must be on or before 'to'")
    return start, end
```
