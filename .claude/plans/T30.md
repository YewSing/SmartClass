# T30 — Four attendance statuses (FR-302–FR-304)

## Goal
Attendance records may only be `present | late | excused | absent`.
- A face recognition (Module 4 → `POST /internal/face-match`, not dry run) records `present`, or `late` when it comes **more than** `ATTENDANCE_LATE_AFTER_MINUTES` (new config, default 15) after the session's effective start (`attendance_sessions.starts_at`, falling back to `opened_at`). Only the first recognition counts (an existing record is never changed by a later recognition).
- `excused` is only ever set by a lecturer override. Closing still marks unrecorded students `absent` (FR-303).
- Data migration: existing `unidentified` records (and any other value outside the four) become `absent`; unidentified faces live only in `face_review_entries`. DB CHECK constraint on `attendance_records.status`.
- API, counts, exports and tests updated.

Done when: the above holds, tests below pass, `bash scripts/check.sh` passes, reviewer finds no real problems.

### 4. `backend/app/services/attendance_service.py`
- New pure function:
```python
def status_for_recognition(session: AttendanceSession, detected_at: datetime) -> str:
    """FR-302: Present, or Late when the first recognition is more than
    ATTENDANCE_LATE_AFTER_MINUTES after the session's effective start."""
    start = session.starts_at or session.opened_at
    if start is None:
        return "present"
    late_after = start + timedelta(minutes=settings.ATTENDANCE_LATE_AFTER_MINUTES)
    return "late" if detected_at > late_after else "present"
```
  Strictly greater: exactly 15:00 after start is still `present`. A recognition before `starts_at` (early-open window) is `present`.
