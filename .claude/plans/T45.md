# T45 — Student "I'm here" flag, lecturer flag alerts, "attendance recorded" banner [UI]

## Goal
Wire T43 (flags) and T44 (`/ws/me` student channel) into the two phone apps.

- **Student app**: on a class that is open right now and has no record for the student, a button
  "I'm here — not recognised" sends the flag (FR-318). The old mock `AttReportStatus` screen shows
  the real flag (pending → confirmed / rejected with reason, FR-319), updated live. A global banner
  "Attendance recorded for <CODE> · Present" appears when the student's `/ws/me` channel gets
  `attendance_recorded` (FR-406).
- **Lecturer app**: the live session screen lists the session's flags with Confirm / Reject (reason
  required), the closest unmatched crop if any (FR-407), and a toast alert when a new flag arrives
  over the session websocket.

**Done when**: the flag button appears only during an open session with no record; `AttReportStatus`
shows the real flag status; Maestro flows pass: (1) student flags, sees pending, then the result;
(2) lecturer sees the alert and confirms; (3) student sees the banner after a simulated
recognition. Flows (1) and (3) are one student flow (`flag.yaml`), (2) is `flag-alert.yaml`.

## Existing work (reuse)
- Backend is complete; **do not change any `backend/app/` code**. Endpoints (from T43/T44):
  - `POST /student/me/sessions/{id}/flag` → 201 `StudentFlagOut`; 409 with `detail` text when not
    open / already recorded / already flagged; 403 not enrolled.
  - `GET /student/me/flags?session_id=` → `StudentFlagOut[]` newest first:
    `{id, session_id, class_code, class_name, class_date, flagged_at, status (pending|confirmed|rejected), record_status, reject_reason, resolved_at}`.
  - `GET /lecturer/flags?session_id=` → `FlagOut[]` (pending first):
    `{id, session_id, session_status, class_code, class_name, class_date, student_id, name, matric_no, flagged_at, status, record_status, reject_reason, resolved_at, closest_crop: {id, similarity}|null}`.
  - `GET /lecturer/flags/{id}/crop` (image/jpeg, 404 if none), `POST /lecturer/flags/{id}/confirm`,
    `POST /lecturer/flags/{id}/reject {reason}` (blank reason → 422). Both return `FlagOut`.
  - Lecturer WS `/ws/sessions/{id}` events: `{"event":"attendance_flagged","session_id","flag": FlagOut}`,
    `{"event":"attendance_flag_resolved","session_id","flag": FlagOut}`; confirm also sends the
    existing `attendance_update` (roster/counts already handled in `LecturerContext.jsx`).

#### 3. New `src/services/live.js` — the student's own live channel, testable without React
```js
// Student live channel /ws/me (T44): attendance_recorded (FR-406), attendance_flag_resolved (FR-319).
// Reconnects while open; a 1008 close (expired token) refreshes the token once before reconnecting.
export function connectStudentLive({
  baseUrl, getToken, refreshToken, onEvent,
  WebSocketImpl = globalThis.WebSocket, schedule = setTimeout, cancel = clearTimeout,
  retryMs = 3000,
}) -> { close() }
```
Behaviour:
- `open()`: `token = getToken()`; if none, stop (no reconnect). `url = baseUrl.replace(/^http/, 'ws') + '/ws/me?token=' + encodeURIComponent(token)`; `ws = new WebSocketImpl(url)`.
- `ws.onmessage = e => { let data; try { data = JSON.parse(e.data) } catch { return }; if (data?.event && data.event !== 'connected') onEvent(data) }`.
- `ws.onclose = async (e) => { if (closed) return; if (e?.code === 1008) { const ok = await refreshToken(); if (!ok || closed) return } ; timer = schedule(open, retryMs) }`.
  (Refresh at most once in a row: keep a `refreshedOnce` flag that resets on the next `onopen`; a second 1008 in a row stops.)
- `ws.onerror` does nothing (onclose follows).
- `close()`: `closed = true`, `cancel(timer)`, `ws?.close()`.
