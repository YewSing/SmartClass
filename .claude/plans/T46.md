```js
// Server times are naive Malaysia time (no offset); read them as +08:00 whatever the browser's zone
export function parseMyt(iso) {
  if (!iso) return null
  const s = String(iso)
  return new Date(/[zZ]|[+-]\d\d:?\d\d$/.test(s) ? s : `${s}+08:00`)
}

// "Online" / "Offline · last seen 13 Nov, 10:42 am" / "Never connected" / "No key yet" for a device row (NFR-23)
export function deviceStatus(d) {
  if (!d.has_key) return { label: 'No key yet', tone: 'neutral', online: false }
  if (d.online) return { label: 'Online', tone: 'good', online: true }
  if (!d.last_heartbeat_at) return { label: 'Never connected', tone: 'neutral', online: false }
  return { label: `Offline · last seen ${formatMyt(d.last_heartbeat_at)}`, tone: 'bad', online: false }
}

export function formatMyt(iso) {
  const d = parseMyt(iso)
  if (!d || isNaN(d)) return ''
  return d.toLocaleString('en-MY', {
    day: 'numeric', month: 'short', hour: 'numeric', minute: '2-digit', timeZone: 'Asia/Kuala_Lumpur',
  })
}

// Checks the "Register device" form before it is sent. Returns a message or null.
export function newDeviceError({ name = '', room = '' }) {
  if (!name.trim() || !room.trim()) return 'Enter a device name and a room.'
  if (name.trim().length > 255 || room.trim().length > 255) return 'Keep the name and room under 255 characters.'
  return null
}
```
Order rule in `deviceStatus`: an online device always has a key, so `has_key` is checked first. A device without a key cannot send heartbeats, so "No key yet" wins.

## Traps
- **No backend API or schema change.** No migration. Do not edit `routers/admin_devices.py`. If something seems missing there, stop and write it under Blocked; don't change the API.
- The key is a secret:
  - Never `console.log` it.
  - Never put it in context, AsyncStorage or localStorage.
  - Don't keep it after `Done`.
  - The E2E keeps keys only in memory.
  - Don't commit any key or `backend/.env`.
- Use **inline confirms, not RN `Modal`**: toasts hide behind Modal (see PROGRESS Next).
- Timestamps are naive MYT. `new Date('2026-11-13T10:42:00')` would read them in the browser's zone, so always go through `parseMyt` and `formatMyt`.
- Seeded cameras (`CAM-TEST` etc.) have `has_key=false`, so their button says "Issue key", not "Regenerate key". Don't touch them in the E2E: use only the `E2E T46 <time>` room, so it never 409s against seeded rooms and cleanup can't hit real devices.
- `device-status`: `deviceStatus` returns `Offline · last seen …` for old heartbeats. The E2E asserts exact `Never connected` / `Online` only on its own fresh device.
- The Playwright backend runs with `SESSION_SCHEDULER_INTERVAL_SECONDS=0` and similar settings. The heartbeat goes to the same `:8001` backend through `API`, so keep using the `API` constant, not a hard-coded 8000.
- Expo web renders each tab's screen into the DOM, sometimes twice (hidden copies). That is why `admin.spec.js` uses `visible(...)`. Use `visible()` for every page-level locator in the new spec.
- `navigator.clipboard` is missing on non-secure origins other than localhost. Guard it, and don't make the test depend on Copy.
- Never weaken a test. The `admin.spec.js` edit only adds a tab to the arrays it checks, so no `TEST-CHANGE` line is needed. If an existing web test fails for reasons unrelated to this task, leave it failing and write it in PROGRESS.md.
- Scope: don't build the NFR-23 "room device online on the lecturer's session screen" here (PROGRESS Next T40). Don't touch `frontend/admin` (T96 retires it). This is Yew Sing's M4 only.
