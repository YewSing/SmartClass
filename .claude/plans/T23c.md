# T23c — Admin Accounts shows a pending face submission

## Goal
In Yew Sing's T23 retest (2026-11-12) a student's face submission sat in the review queue while the admin Accounts screen said "No face data", because Accounts only looks at `face_enrolled` (embeddings exist).

Done when:
- `GET /admin/users` items and the user detail (`GET /admin/users/{id}`, plus the POST/PUT responses that share the builder) carry `face_status` for students, using the same rule as `face_enrolment_service.enrolment_status`. The list gets all statuses for the page in **one** query, not one per user.
- The admin Accounts screen (lecturer web app) shows an amber "Pending review" badge instead of "No face data" while a submission waits, with a link that opens the Face verification tab.
- Tests: an API test for each status, a no-N+1 test, and a Playwright `admin.spec.js` case where a seeded pending submission shows "Pending review".

**Status words.** The task text says `none`, but the API already uses `not_enrolled` for this state (`/auth/me` `face_status`, `GET /student/face/status`, from `enrolment_status`). Use the **existing words**: `not_enrolled | pending_review | active | rejected`, and `null` for non-students. The same field name (`face_status`) must not mean different words on two endpoints. Write this decision in the log.

## Existing work

### 1. `backend/app/services/face_enrolment_service.py`
Add below `enrolment_status` (imports: add `Student` from `app.models.user`; `select` and `func` are already imported):

```python
def status_word(has_face: bool, last_status: str | None) -> str:
    """The rule of enrolment_status as a word, for lists (embeddings win, then the latest
    non-blocked submission if it waits or was rejected)."""
    if has_face:
        return "active"
    if last_status in ("pending_review", "rejected"):
        return last_status
    return "not_enrolled"


async def enrolment_statuses(db: AsyncSession, student_ids: list[int]) -> dict[int, str]:
    """Face enrolment status per student (students.id) in one query, for the admin account list."""
    if not student_ids:
        return {}
    has_face = (select(FaceEmbedding.id)
                .where(FaceEmbedding.student_id == Student.id)
                .exists())
    last_status = (select(FaceEnrolment.status)
                   .where(FaceEnrolment.student_id == Student.id, FaceEnrolment.status != "blocked")
                   .order_by(FaceEnrolment.id.desc())
                   .limit(1)
                   .correlate(Student)
                   .scalar_subquery())
    rows = await db.execute(select(Student.id, has_face, last_status).where(Student.id.in_(student_ids)))
    return {sid: status_word(face, last) for sid, face, last in rows}
```
Do **not** rewrite `enrolment_status`. The parity test below keeps the two from drifting apart.
If importing `Student` in this module causes a circular import (check: `python -c "import app.main"`), import it inside the function instead.

```js
// Face enrolment on an account row (FR-115, FR-117). Falls back to face_enrolled for an older server.
const FACE_STATUS = {
  active:         { label: 'Face enrolled',  tone: 'good' },
  pending_review: { label: 'Pending review', tone: 'warn' },
  rejected:       { label: 'Face rejected',  tone: 'bad' },
  not_enrolled:   { label: 'No face data',   tone: 'neutral' },
}
export function faceStatus(u) {
  if (u.role !== 'student') return null
  const key = u.face_status ?? (u.face_enrolled ? 'active' : 'not_enrolled')
  return { key, ...(FACE_STATUS[key] ?? FACE_STATUS.not_enrolled) }
}
```
