# T44 — Recognition feedback events (FR-406, NFR-12)

## Goal
When a student gets a **Present** or **Late** record (camera recognition, the old `/internal/face-match`
path, or a lecturer confirming their "not recognised" flag), two live events go out after the DB commit:
1. the lecturer's session channel (`/ws/sessions/{id}`) gets `attendance_update` — this already happens;
2. **new:** the student's own channel gets `attendance_recorded` ("Attendance recorded for CS101").

Also new: `app/services/notify.py` with `async def emit(event, user_ids, payload)`, the hook Module 2
(Shino) will later wire to push/in-app/email. For now it only logs. It is called with
`attendance.recorded` for the student. Documented in `docs/interfaces.md`.

Done when: student channel exists and receives `attendance_recorded` on Present/Late (and
`attendance_flag_resolved` when their flag is confirmed or rejected — T43's log hands this to T44);
`notify.emit` exists, logs only, is documented; tests pass.

## Changes

### 1. `backend/app/websocket/manager.py`
Add a second map for per-user channels, keeping the session API unchanged:
```python
self._user_connections: dict[int, set[WebSocket]] = {}

async def connect_user(self, user_id: int, ws: WebSocket) -> None:   # ws.accept() then add
def disconnect_user(self, user_id: int, ws: WebSocket) -> None:       # discard
async def send_to_user(self, user_id: int, payload: dict) -> None:   # same dead-socket handling as broadcast
```
Update the class docstring: session channels for lecturers, user channels for a student's own events (FR-406).

### 2. `backend/app/websocket/router.py` — new endpoint
```python
@router.websocket("/ws/me")
async def student_ws(websocket: WebSocket, token: str = Query(...)):
```
- Decode token like `attendance_ws`. Close with 1008 (without accepting) unless: `sub` present, `type == "access"`, `role == "student"`, and the `User` row exists with `status == "active"` (load it with `AsyncSessionLocal()`; same rule as `core/deps.get_current_user`). A deactivated student must not get a channel.
- `await manager.connect_user(user_id, websocket)`, then send `{"event": "connected", "user_id": user_id}` (lets clients and tests know the channel is live).
- Loop `await websocket.receive_text()` until `WebSocketDisconnect`; `finally: manager.disconnect_user(user_id, websocket)`.
- Docstring: "A student's own live events: attendance_recorded (FR-406), attendance_flag_resolved (FR-319). Authenticate via ?token=<JWT>."
- No DB session kept open during the receive loop (close the `async with` before the loop — unlike `attendance_ws`, there is no initial state to read).

### 3. New `backend/app/services/notify.py`
```python
"""Notification hook for Module 2 (Dashboard & Notifications, Shino). ..."""
import logging
from collections.abc import Iterable
log = logging.getLogger(__name__)

async def emit(event: str, user_ids: Iterable[int], payload: dict) -> None:
    """Raise a notification event for `user_ids` (users.id). Module 2 replaces or wraps this to

```
- Body: `ids = sorted(set(user_ids))`; if empty return; `log.info("notify %s -> users %s", event, ids)`. **Do not log the payload** (it holds names/matric numbers — NFR-02/PDPA). Wrap in try/except Exception → `log.warning` so a notification can never fail a request.
- Module docstring lists the events and payloads currently raised (only `attendance.recorded` now) and says the other events from FR doc Module 2 (`attendance.flagged`, `face_enrolment.*`) are not raised yet.

### 4. `backend/app/services/attendance_service.py::broadcast_attendance_update`
Keep the lecturer payload and `_announce` behaviour exactly as is. Add, **before** `after_commit` (DB reads must happen before commit, not in the callback):
```python
student_event = None
student_user_id = None
if record.status in ATTENDED_STATUSES:
    student_user_id = await db.scalar(select(Student.user_id).where(Student.id == record.student_id))
    course = (await db.execute(
        select(Course.code, Course.name)
        .join(ClassOccurrence, ClassOccurrence.course_id == Course.id)
        .join(AttendanceSession, AttendanceSession.occurrence_id == ClassOccurrence.id)
        .where(AttendanceSession.id == session_id)
    )).one_or_none()
```
If `student_user_id` and `course` are both found (`code, name = course`), build:
```python
student_event = {
    "event": "attendance_recorded",
    "session_id": session_id,
    "course_code": code,
    "course_name": name,
    "status": record.status,                     # "present" | "late"
    "detected_at": record.detected_at.isoformat() if record.detected_at else None,
    "source": record.source or "recognition",    # "student_flag" when a flag was confirmed
    "message": f"Attendance recorded for {code}",
}
```
Otherwise (session without occurrence, missing student) leave `student_event = None`.
In `_announce()` after the existing lecturer broadcast **and before** `check_low_attendance_alert`:
```python
if student_event is not None:
    await manager.send_to_user(student_user_id, student_event)
    await notify.emit("attendance.recorded", [student_user_id], student_event)
```
Imports: `ATTENDED_STATUSES` from `app.models.attendance`, `Student` from `app.models.user`, `ClassOccurrence, Course` from `app.models.class_`, `from app.services import notify`. Check for circular imports (`app.services.notify` imports nothing from app — keep it that way).
Update the function docstring: "Announce a new Present/Late record once `db` commits: `attendance_update` to the lecturer's session channel, `attendance_recorded` to the student's channel and `notify.emit('attendance.recorded')` for Module 2 (FR-406)."

## Traps
- **After commit only.** All new sends go inside the existing `after_commit` callbacks. Do not `await manager.send_to_user` directly in a request path. DB queries for the student payload go *before* `after_commit`, not inside `_announce` (the callback runs after commit; reading there works today for `check_low_attendance_alert` but don't add more of that).
- `record.student_id` is `students.id`; channels are keyed by **`users.id`**. Mixing them up sends to the wrong person — test 1 asserts the user id explicitly.
- Never log the payload in `notify.emit` (names, matric numbers: NFR-02/PDPA). Never print secrets or read `backend/.env`.
- Only Present/Late trigger `attendance_recorded`; overrides by the lecturer (`routers/attendance.py`) do **not** send a student event in this task (out of scope; note under Next).
- Module 2 is Shino's: build only the `emit` stub. Don't create notification tables, push tokens, or email.
- Don't change the lecturer `attendance_update` payload shape or the `/ws/sessions` endpoint; the lecturer app depends on them.
- Don't delete/skip/weaken any existing test. If an existing test breaks, fix the code, not the test.
- No schema change, no migration.
- Keep `app/services/notify.py` free of `app.*` imports (it will be wrapped by M2; avoids cycles).
