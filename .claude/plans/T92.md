# T92 — YouTube suggestions (FR-812, Could Have)

## Files to change
- `backend/app/core/config.py` — `YOUTUBE_API_KEY` (default ""), `YOUTUBE_MAX_RESULTS` (5).
- `backend/app/services/kb/youtube.py` — `search_videos(topic)`: YouTube Data API search behind the
  key; off (no call, `enabled=False`) when the key is empty; degrades to empty videos on error.
- `backend/app/schemas/assistant.py` — `YoutubeVideo`, `YoutubeOut`.
- `backend/app/routers/assistant.py` — `POST /student/assistant/youtube {course_id, topic}`.
- `backend/tests/test_youtube.py` — mocked (respx) tests.

## Approach
A "Could Have" external-resource helper, not part of the knowledge base. The endpoint takes a
course the student is enrolled in plus a topic, and returns suggested videos (title, channel, URL,
thumbnail) plus a few search keywords derived from the topic. No LLM call.

## Edge cases
- Empty `YOUTUBE_API_KEY` → feature off: `enabled=False`, no HTTP call, empty videos (keywords still
  returned so the student can search manually).
- YouTube error / bad JSON → empty videos, `enabled=True` (the request was attempted).
- Enrollment/access mirrors the summary endpoint (`_student_only` + `_enrolled_course`).

## Tests
- `tests/test_youtube.py` (respx): with a key → videos parsed from a mocked search response; empty
  key → no call + `enabled=False`; HTTP 403 → empty videos; enrollment 403; schema shape.
