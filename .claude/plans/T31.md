# T31 — Override with mandatory reason + full audit (FR-305, NFR-06)

## Goal
Both attendance override endpoints must require a non-empty `reason`. A missing, empty or
whitespace-only reason gives **422** and changes nothing. Every override writes one
`ATTENDANCE_OVERRIDE` audit row holding actor, old status, new status, reason and time.
Only the class's lecturer may override. That check already exists (`_get_taught_session`), and
`tests/test_lecturer_access.py` must keep passing. The T02 characterisation tests that override
without a reason are updated to send one, each with a `TEST-CHANGE:` line in PROGRESS.md.

Done when: the above holds, the new tests pass, and `bash scripts/check.sh` passes.

## Existing work
- `backend/app/routers/attendance.py`
  - `override_attendance` handles `PUT /attendance/{record_id}/override`, body `OverrideRequest`.
  - `override_session_attendance` handles `PUT /lecturer/sessions/{session_id}/attendance/override`, body `SessionOverrideRequest`, and creates the record if it is missing (`old_status = "not_recorded"`).

  - Tests: `tests/test_char_attendance.py` (lines ~57, 80, 82, 88, 97, 113, 123, plus the export test's override), `tests/test_char_sessions.py:44`, `tests/test_attendance_statuses.py` (~254, 261, 287, 291), `tests/test_session_schedule.py:179, 572`, `tests/test_lecturer_access.py:31-32`.
  - App: `mobile/lecturer/src/services/api.js:196` `overrideAttendance`. **Not changed in T31**; see Traps.

## Changes

### 1. `backend/app/schemas/session.py`
Add a shared reason type and use it in both request models:
```python
from typing import Annotated, Optional
from pydantic import BaseModel, Field, StringConstraints

OverrideReason = Annotated[str, StringConstraints(strip_whitespace=True, min_length=1, max_length=500)]

class OverrideRequest(BaseModel):
    status: str  # present | late | excused | absent
    reason: OverrideReason  # FR-305: mandatory, audited

class SessionOverrideRequest(BaseModel):
    student_id: int
    status: str  # present | late | excused | absent
    reason: OverrideReason  # FR-305: mandatory, audited
```
Missing, `""`, `"   "` and over-500-character reasons all give 422 from FastAPI validation. The stored reason is the stripped string.

### 2. `backend/app/routers/attendance.py`
- `override_attendance`: change the `write_log` call to
  `old_val={"status": old_status}, new_val={"status": body.status, "reason": body.reason}`.
  Nothing else changes: the status check still gives 400 and ownership still gives 403/404.
- `override_session_attendance`: the same `new_val={"status": body.status, "reason": body.reason}`.
- Update both docstrings or comments to say a reason is required (FR-305). Do not touch the WS broadcast payload or `AttendanceStudentOut`.
- Validation order to keep: a valid body with a bad status still gives **400** (existing tests), and a missing reason gives **422** before any handler code runs, so no record or audit row is written.

### 3. `frontend/admin/src/views/AuditLogView.jsx` (one line, line ~67)
```js
case 'ATTENDANCE_OVERRIDE':
  return ov?.status && nv?.status
    ? `${ov.status} → ${nv.status}${nv.reason ? ` · "${nv.reason}"` : ''}` : null
```
Old entries have no reason and still show `old → new`.

No migration, no model change: the reason lives in the audit row's `new_val` JSON.
