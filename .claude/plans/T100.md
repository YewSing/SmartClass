# T100 — Lecturer asks their own materials (FR-815)

## Files to change
- `backend/app/models/ai_chat.py` — `ChatSession.student_id` becomes nullable; add `lecturer_id`
  (nullable FK → `lecturers.id`, ondelete CASCADE, indexed) + a `CheckConstraint` enforcing
  exactly one owner (`(student_id IS NOT NULL) <> (lecturer_id IS NOT NULL)`).
- `backend/alembic/versions/<new>_chat_single_owner.py` — migration (down_revision `d1e2f3a4b5c6`).
- `backend/app/services/kb/assistant.py` — guard the quiz lock: only call `get_active_attempt`
  when `session.student_id is not None` (lecturers have no quiz lock; same answer code otherwise).
- `backend/app/services/kb/trends.py` — add `AND s.student_id IS NOT NULL` to all three SQL
  queries so a lecturer's own chat is never counted in question trends (FR-815).
- `backend/app/routers/assistant.py` — lecturer endpoints (see below).
- `backend/app/schemas/assistant.py` — reuse `SessionOut`/`MessageOut`/`AssistantCourseOut`
  (no ownership field exposed; the caller already knows its role). No new schema needed.
- `backend/tests/conftest.py` — `synthetic_kb` returns `lecturer_id` (for live + mock tests).

## Approach
Mirror the student chat endpoints under `/lecturer/assistant/…`, owner = `lecturer_id`, using
the exact same `answer_question` code so citations/labels are identical:

- `GET  /lecturer/assistant/courses` — courses the lecturer teaches + indexed-material counts
  (same shape as the student list; teaching = assigned to any `ClassOccurrence` of the course).
- `GET  /lecturer/assistant/sessions?course_id=`
- `POST /lecturer/assistant/sessions`
- `PATCH /lecturer/assistant/sessions/{id}`
- `DELETE /lecturer/assistant/sessions/{id}`
- `GET  /lecturer/assistant/sessions/{id}/messages`
- `POST /lecturer/assistant/sessions/{id}/messages` — `answer_question`, 503 on `LLMUnavailable`.

Helpers (new, beside the existing student ones): `_lecturer(db, user)` (404 if no Lecturer row),
`_teaches_course(db, lecturer_id, course_id)` (403 unless they teach it), `_own_lecturer_session`.
Role dependency: `require_role("lecturer")` so students/admins get 403.

## Edge cases
- A lecturer session has `student_id = NULL`; `_history`, `_standalone_query`, `_label_topic` and
  `parse_answer` are owner-agnostic. Only the quiz lock reads `student_id`.
- Other lecturer asks / lists a course they don't teach → 403.
- Student or admin hits a lecturer endpoint → 403.
- Lecturer asking in a course with no indexed materials still answers general-knowledge (same as
  students); fake LLM must return a course answer when passages exist, general otherwise.
- `SessionOut` keeps working for lecturer sessions (no `student_id` exposed).

## Tests
