# T34 — Moodle Attendance plugin in the simulated SPeCTRUM

## Goal
The local Moodle (`backend/moodle/`) gets the `mod_attendance` plugin so T35 can sync closed SmartClass sessions into it.

Done when: `backend/moodle/scripts/setup.sh` installs `mod_attendance` (the version for Moodle 4.5) and can be re-run safely; it adds the plugin's web-service functions to the `smartclass` service; `seed.sh` adds one Attendance activity to each seeded course; student self-marking stays off; a `moodle` test calls `mod_attendance_get_sessions` successfully. `bash scripts/check.sh` passes (the loop runs it) and the reviewer finds no real problems.

No backend app code, API or DB schema changes in this task.

## Changes

### 1. New `backend/moodle/scripts/install_attendance.php` (plain PHP, does NOT load Moodle's config.php)
Run as `daemon` inside the container. Steps:
```php
<?php
// Installs mod_attendance (pinned to the MOODLE_405_STABLE commit below) into /bitnami/moodle/mod/attendance.
// Idempotent: does nothing when that version is already there. Moodle's upgrade.php then registers it.
// Run: docker exec -u daemon smartclass-moodle-moodle-1 php /scripts/install_attendance.php
const SHA = '7985321ce811bdbc0f9728c0918518b8b5936bae';
const VERSION = 2024082404;
$dest = '/bitnami/moodle/mod/attendance';
$stage = '/bitnami/moodle/.smartclass_stage';   // same filesystem as $dest, so rename() works
```
- Helper `installed_version(string $dir): ?int` — read `$dir/version.php` text, `preg_match('/\$plugin->version\s*=\s*(\d+)/', ...)`, return int or null.
- If `installed_version($dest) === VERSION`: echo `mod_attendance already installed (VERSION)` and exit 0.
- Else: download the zip URL with `file_get_contents` (on false: write `Download failed` to STDERR, exit 1); write it to `$stage/attendance.zip` (create `$stage` with `mkdir(..., 0775, true)` after removing any old `$stage` with a recursive delete helper `rrmdir(string $dir): void`); open with `ZipArchive`, `extractTo($stage)`, close.
- `$src = "$stage/moodle-mod_attendance-" . SHA`; if `installed_version($src) !== VERSION` → STDERR `Unexpected plugin version in download`, `rrmdir($stage)`, exit 1.
- If `$dest` exists (other version): `rrmdir($dest)`. Then `rename($src, $dest)`; `rrmdir($stage)`; echo `Installed mod_attendance VERSION`.
- `rrmdir` must handle files, symlinks and nested dirs (use `RecursiveIteratorIterator(new RecursiveDirectoryIterator($dir, FilesystemIterator::SKIP_DOTS), RecursiveIteratorIterator::CHILD_FIRST)`; `rmdir` dirs, `unlink` the rest; no-op when `$dir` does not exist).

```php
$attmod = $DB->get_record('modules', ['name' => 'attendance']);
if (!$attmod) {
    echo "!! mod_attendance not installed (run setup.sh); no Attendance activities added\n";
} else {
    foreach ($conf['courses'] as $c) {
        $short = $c['shortname'];
        if (empty($courses[$short])) continue;          // dry run on a new course
        $course = $courses[$short];
        if ($DB->record_exists('attendance', ['course' => $course->id])) { echo "attendance exists: $short\n"; continue; }
        echo "add attendance: $short\n";
        if ($dry) continue;
        $mi = new stdClass();
        $mi->modulename = 'attendance'; $mi->module = $attmod->id;
        $mi->name = 'Attendance'; $mi->intro = 'Synced from SmartClass. Students do not mark themselves.';
        $mi->introformat = FORMAT_HTML;
        $mi->section = 0; $mi->visible = 1; $mi->visibleoncoursepage = 1;
        $mi->cmidnumber = ''; $mi->groupmode = NOGROUPS; $mi->groupingid = 0;
        add_moduleinfo($mi, $course);
    }
}
```

## Tests

New file `backend/tests/test_moodle_attendance.py` — `moodle` marker only (no `db`: no SmartClass DB needed). Module docstring: `"""T34: mod_attendance in the local SPeCTRUM simulation (needs backend/moodle up + setup.sh + seed.sh)."""`

Helper:
```python
async def _attendance_id(client: MoodleClient, shortname: str) -> int:
    course_id = await client.get_course_id(shortname)
    assert course_id, f"{shortname} not in Moodle (run seed.sh)"
    sections = await client.call("core_course_get_contents", courseid=course_id)
    ids = [m["instance"] for s in sections for m in s.get("modules", []) if m.get("modname") == "attendance"]
    assert len(ids) == 1, f"{shortname} should have exactly one Attendance activity, found {ids}"
    return ids[0]
```

1. `test_every_seeded_course_has_one_attendance_activity` (`@pytest.mark.moodle`, parametrize over `["WIF3001", "WIF3004", "WIA2005", "WIA0000"]`): `async with MoodleClient() as c: await _attendance_id(c, shortname)`.
2. `test_get_sessions_works_with_service_token` (`@pytest.mark.moodle`): with the service token, `body = await c.call("mod_attendance_get_sessions", attendanceid=await _attendance_id(c, "WIA0000"))`; assert `isinstance(body, list)` (empty is fine).
3. `test_service_can_add_and_remove_a_session_with_four_statuses` (`@pytest.mark.moodle`): attendance id for WIA0000; `add = await c.call("mod_attendance_add_session", attendanceid=aid, description="T34 test", sessiontime=int(time.time()), duration=3600, addcalendarevent=0)`; `sid = add["sessionid"]`; in `try:` `sess = await c.call("mod_attendance_get_session", sessionid=sid)`; assert `sess["studentscanmark"] == 0`; assert `{s["acronym"] for s in sess["statuses"]} >= {"P", "L", "E", "A"}`; assert `sid in [s["id"] for s in await c.call("mod_attendance_get_sessions", attendanceid=aid)]`; `finally:` `await c.call("mod_attendance_remove_session", sessionid=sid)` (so repeated runs leave no sessions behind).
4. `test_student_token_cannot_read_attendance_sessions` (`@pytest.mark.moodle`): `aid` via the service client; `tok = await get_user_token("student1", "Student123!")`; `async with MoodleClient(token=tok) as s:` `with pytest.raises(MoodleError): await s.call("mod_attendance_get_sessions", attendanceid=aid)`. (Students can reach the `smartclass` service, so this proves the plugin's capability checks keep them out.)

Imports: `time`, `pytest`, `from app.services.kb.moodle_client import MoodleClient, MoodleError`, `from app.services.moodle_auth import get_user_token`. pytest-asyncio runs in auto mode (`pytest.ini`), so plain `async def` tests are fine.

- Run every `docker exec` PHP as `-u daemon` (root-owned files break Moodle: README). `MSYS_NO_PATHCONV=1` is already exported in the scripts; keep it.

- Do not commit the plugin's code; it is downloaded at setup time into the Docker volume.
- `configure_moodle.php` must run after the upgrade (the `mod_attendance_*` functions only exist in `external_functions` once the plugin is installed).

- No SmartClass sync code here: that is T35. Don't add a mapping table, sync status or settings.
